# 内容运营校准师 · 专家团对话窗口

一个**单文件网页**：接收多平台运营数据，由三位专家串行处理，产出带证据的校准动作卡。

## 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 浏览器端**实时计算**的判定引擎（四条规则、指标口径、复核逻辑全部前端执行） | 不是预录动画、不是写死卡片的静态展示页 |
| 三专家串行对话：数据采集员 → 业务判断员 → 质量复核员（团长） | 不是单次问答冒充智能体 |
| 公网用**虚构示例数据**自洽演示全流程 | 示例数据不是真实账号数据 |
| 本机可切换「贴主页链接」接数据网关抓真实公开数据 | 公网页面读不到本机服务（浏览器安全规则，非故障） |

**单一作品名**：本页与提交材料、平台侧专家团使用同一个名字「内容运营校准师」，不另起第二个名字。

## 本地运行

双击 `index.html` 用浏览器打开即可，零依赖、零构建、零外部请求。

两种数据来源：

1. **示例数据（默认）**：点「载入回归用例」或「载入边界用例」，再点「开始校准」。公网上也能跑，因为计算全在浏览器里。
2. **贴主页链接（需本机网关）**：在本机启动看山数据网关（8686 端口），再贴知乎用户主页链接。网关未开时会如实提示失败、不编数据。

## 规则口径（与定稿技能包一致）

- **互动率** =（点赞+评论）÷ 曝光；曝光 0 记 0，不除零。
- **阈值判定用原始值**，四舍五入仅用于展示；0.019975（<0.02）触发 R1，恰好 0.02 不触发。
- **R1** 互动率<0.02（优先级1）；**R2** 粉丝<100（优先级2）；**R3** 曝光>0且点赞=0（优先级2）；**R4** 全体零卡时补 1 张全局兜底卡（优先级3）。
- 同一平台多条命中分别出卡，不合并、不去重。
- 缺字段标「未获取」不补零；取数失败平台只进数据可用性、不出卡。

## 验收

`test_engine.js` 从网页抽取规则函数真跑定稿回归用例，覆盖三个边界陷阱：

```bash
node test_engine.js
# 期望：ALL_PASS（回归4卡 / 边界1卡 / R4兜底 / 缺字段）
```

## 诚实边界

- 本页是**能力演示窗口**，不是参赛作品本体，不构成任何平台合规证明。
- 规则判定结果是确定性计算，可复现；示例数据为虚构。
- 真实取数模式依赖本机网关与登录态，登录态绝不写进网页或公开仓库。
- 与「小浣熊平台内的专家团对象」是两层：本页演示规则与流程，平台侧对象与留痕须本人在客户端产生。
